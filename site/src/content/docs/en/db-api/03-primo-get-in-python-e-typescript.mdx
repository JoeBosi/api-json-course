## Goals

- Make a `GET` from Python (`httpx`) and from TypeScript (`fetch`) and read status, headers and body.
- Pass query parameters without writing them into the URL by hand.
- Understand the **envelope** of list responses: `items`, `meta`, `links`.
- Turn an error status into an exception (or an `if`) instead of ignoring it.

## Theory

### The two libraries

| | Python: `httpx` | TypeScript: `fetch` |
|---|---|---|
| Installation | `pip install httpx` | none: built into Node ≥ 18 and browsers |
| Call | `httpx.get(url, params=…, headers=…)` | `await fetch(url, { headers })` |
| Status | `r.status_code` (int) | `r.status` (number), `r.ok` (true if 2xx) |
| Headers | `r.headers["content-type"]` (case-insensitive dict) | `r.headers.get("content-type")` |
| JSON body | `r.json()` → `dict`/`list` | `await r.json()` → object/array |
| Text body | `r.text` | `await r.text()` |
| Error on 4xx/5xx | **no**, until you call `r.raise_for_status()` | **no**: `fetch` throws only on network errors; `r.ok` must be checked |
| Query string | `params={"limit": 3}` → automatic encoding | `new URL(...)` + `url.searchParams.set(...)` |

<Aside type="tip" title="Why httpx and not requests?">
`requests` still works perfectly well and has the same shape (`requests.get(...)`, `.json()`, `.raise_for_status()`). `httpx` has the same API, and in addition supports HTTP/2, `async` and a `Client` with a `base_url`. Everything you see here also applies to `requests`, changing the module name.
</Aside>

### The list envelope

When you ask for a **collection** (`/books`, `/authors`, `/orders`…) this server — like many APIs — does not return a bare array but an object:

```json
{
  "items": [ … ],                                   ← i dati veri
  "meta":  { "page": 1, "limit": 3, "total": 80, "pages": 27 },   ← quanti sono, dove sei
  "links": { "self": "…", "next": "…?page=2&limit=3", "prev": null }  ← come continuare
}
```

Why? A bare array cannot say "there are 77 more". The envelope can, and it lets you add fields in the future without breaking clients. **Single** resources (`/books/1`), on the other hand, are just the object.

## Python and TypeScript

<Tabs syncKey="lang">
<TabItem label="Python">
```python
# pip install httpx  →  python3 primo_get.py
import httpx

r = httpx.get(
    "https://corso-api-json.giuseppebosi.com/api/v1/books",
    params={"limit": 3, "sort": "-price"},   # httpx costruisce e codifica la query string
)
print(r.status_code, r.headers["content-type"])   # 200 application/json
r.raise_for_status()      # se lo status è 4xx/5xx solleva httpx.HTTPStatusError: meglio fermarsi qui

dati = r.json()           # dict Python
print("totale libri:", dati["meta"]["total"])
for libro in dati["items"]:
    print(f'{libro["id"]:>3}  {libro["title"]:<32} {libro["price"]:>6.2f} €')
print("pagina successiva:", dati["links"]["next"])
```

Output:

```
200 application/json
totale libri: 80
 12  Quello che resta di Sestri        34.49 €
 79  Ustica e il Novecento             34.36 €
 29  La cucina di Ustica               33.49 €
pagina successiva: https://corso-api-json.giuseppebosi.com/api/v1/books?sort=-price&page=2&limit=3
```
</TabItem>
<TabItem label="TypeScript">
```ts
// node --experimental-strip-types primo_get.ts   (Node 22; da Node 23 senza flag)
const url = new URL("https://corso-api-json.giuseppebosi.com/api/v1/books");
url.searchParams.set("limit", "3");        // URL costruisce e codifica la query string
url.searchParams.set("sort", "-price");

const r = await fetch(url);
console.log(r.status, r.headers.get("content-type"));   // 200 application/json
if (!r.ok) throw new Error("HTTP " + r.status);          // fetch non lancia da solo sui 4xx/5xx

const dati = await r.json();
console.log("totale libri:", dati.meta.total);
for (const libro of dati.items) {
  console.log(String(libro.id).padStart(3), libro.title.padEnd(32), libro.price.toFixed(2), "€");
}
console.log("pagina successiva:", dati.links.next);
```

Output:

```
200 application/json
totale libri: 80
 12 Quello che resta di Sestri       34.49 €
 79 Ustica e il Novecento            34.36 €
 29 La cucina di Ustica              33.49 €
pagina successiva: https://corso-api-json.giuseppebosi.com/api/v1/books?sort=-price&page=2&limit=3
```
</TabItem>

Three things to notice:

1. **The parameters are not written into the URL by hand**: `params=` / `searchParams.set` encode them (a space becomes `%20`, a `&` inside a value becomes `%26`).
2. **`r.json()`** is synchronous in Python; in JavaScript it returns a *Promise* and must be awaited (the body can arrive in pieces).
3. **The status must be checked**: `raise_for_status()` and `if (!r.ok)`. In chapter 7 we will do it properly.

### A single resource

<Tabs syncKey="lang">
<TabItem label="Python">
```python
import httpx
libro = httpx.get("https://corso-api-json.giuseppebosi.com/api/v1/books/12").raise_for_status().json()
print(libro["title"], "-", libro["attributes"]["format"])   # Quello che resta di Sestri - …
```

`raise_for_status()` returns the response itself, so it can be chained.
</TabItem>
<TabItem label="TypeScript">
```ts
const r = await fetch("https://corso-api-json.giuseppebosi.com/api/v1/books/12");
if (!r.ok) throw new Error("HTTP " + r.status);
const libro = await r.json();
console.log(libro.title, "-", libro.attributes.format);   // Quello che resta di Sestri - …
```

## Exercise

Write a script that calls `/api/v1/authors?limit=5` and prints, for each author, `name`, `country` and `books_count`. Then print how many pages there are in total (`meta.pages`). Bonus: call `/api/v1/authors/9999` and watch what your script does *without* a status check.

<details>
<summary>Solution</summary>

<Tabs syncKey="lang">
<TabItem label="Python">
```python
import httpx
r = httpx.get("https://corso-api-json.giuseppebosi.com/api/v1/authors", params={"limit": 5})
r.raise_for_status()
d = r.json()
for a in d["items"]:
    print(f'{a["name"]:<20} {a["country"]}  libri: {a["books_count"]}')
print("pagine:", d["meta"]["pages"])
```

Without `raise_for_status()`, `/authors/9999` returns 404 and `r.json()` gives you `{"error": {...}}`: the script carries on and hits a `KeyError` later, far from the cause.
</TabItem>
<TabItem label="TypeScript">
```ts
const r = await fetch("https://corso-api-json.giuseppebosi.com/api/v1/authors?limit=5");
if (!r.ok) throw new Error("HTTP " + r.status);
const d = await r.json();
for (const a of d.items) console.log(a.name.padEnd(20), a.country, " libri:", a.books_count);
console.log("pagine:", d.meta.pages);
```

Without `if (!r.ok)`, `/authors/9999` throws nothing: `d.error` exists and `d.items` is `undefined` → a `TypeError` later on.
</TabItem>

## Common mistakes

- **Building the URL with an f-string / template string** and unencoded values: `f"...?q={testo}"` with `testo = "le estati"` sends a bare space. Use `params=` / `searchParams`.
- **Forgetting `await`** on `r.json()` in JavaScript: you get a Promise, not the data.
- **Trusting an implicit 200**: without `raise_for_status()`/`r.ok`, a 404 looks like "strange data".
- **Looking for the data in a list response as if it were an array**: `dati[0]` → `KeyError`; the books are in `dati["items"]`.
