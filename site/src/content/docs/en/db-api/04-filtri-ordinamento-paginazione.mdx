## Goals

- Combine several filters in the query string and know which values each one accepts.
- Sort with `sort=field` / `sort=-field`.
- Understand **offset** pagination (`page`/`limit`) and its limits; read `meta` and `links`.
- Write a loop that downloads **all** pages by following `links.next`, in Python and TypeScript.
- Recognize parameter errors (400, 422) before they turn into bugs.

## Theory

### Filtering

A collection can have thousands of elements: the client says *which ones* it wants with query parameters. On `/api/v1/books` these are available:

| Parameter | What it does | Example |
|---|---|---|
| `q` | text contained in the title (`LIKE %q%`, case-insensitive) | `q=trieste` |
| `author_id` | books by an author (foreign key) | `author_id=4` |
| `category` | category **slug**, **subcategories included** | `category=narrativa` also takes gialli (crime), fantascienza (sci-fi), storici (historical) |
| `tag` | books with that tag (N-N relation) | `tag=premio` |
| `min_price`, `max_price` | price range (inclusive) | `min_price=10&max_price=20` |
| `year_from`, `year_to` | publication year range | `year_from=2000` |
| `language` | language code | `language=en` |
| `in_stock` | `true`/`false` | `in_stock=true` |
| `format` | value of `attributes.format`, a **JSON column** | `format=tascabile` |

Filters combine with **AND**: `category=gialli&max_price=15` = crime **and** under €15. (For OR and complex conditions there is `POST /query`, chapter 11.)

Values reach the server as **strings**: it is the server that converts them (`min_price=10` → number) and validates them. If you send `min_price=dieci` you get 422.

### Sorting

`sort=price` ascending, `sort=-price` descending: the minus sign before the name is a widespread convention (JSON:API, many REST APIs). Fields allowed here: `id`, `title`, `price`, `year`, `pages`, `created_at`, `rating`. With equal values the server sorts by `id`, so the order is **stable** from one page to the next (without this rule, an element could appear on two pages or on none).

### Paginating

With 80 books fine, with 80,000 no: responses are split into **pages**.

- `limit` = elements per page (default 20 here, **maximum 100**).
- `page` = which page, starting from 1.
- The server computes `OFFSET (page-1)*limit` in the SQL query: this is **offset** pagination. Simple, but with huge offsets it becomes slow and, if someone inserts an element in the meantime, pages "slide". The alternative — **cursor** pagination (`?after=<id>`) — is touched on in chapter 14.

The response tells you where you are and how to carry on:

```json
"meta":  { "page": 1, "limit": 3, "total": 4, "pages": 2 },
"links": { "self": "…page=1…", "next": "…page=2…", "prev": null }
```

`links.next` is **null** on the last page: that is the loop's exit condition. And it already contains all the filters: the client does not have to rebuild anything.

## Python and TypeScript: downloading every page

The pattern is always the same: start from the URL with the filters, then **follow `links.next` until it is null**. Watch one detail: the parameters go only in the **first** request, because `next` already contains them.

<Tabs syncKey="lang">
<TabItem label="Python">
```python
# python3 tutte_le_pagine.py
import httpx

url = "https://corso-api-json.giuseppebosi.com/api/v1/books"
params = {"category": "saggistica", "sort": "-price", "limit": 10}
tutti = []
with httpx.Client() as client:            # un Client riusa la connessione tra le richieste
    while url:
        r = client.get(url, params=params)
        r.raise_for_status()
        dati = r.json()
        tutti.extend(dati["items"])
        print(f'pagina {dati["meta"]["page"]}/{dati["meta"]["pages"]}: {len(dati["items"])} libri')
        url, params = dati["links"]["next"], None   # next contiene già filtri e limit
print(len(tutti), "libri in totale; il più caro:", tutti[0]["title"], tutti[0]["price"])
```
</TabItem>

```ts
// node --experimental-strip-types tutte_le_pagine.ts
let url: string | null = "https://corso-api-json.giuseppebosi.com/api/v1/books?category=saggistica&sort=-price&limit=10";
const tutti: { title: string; price: number }[] = [];
while (url) {
  const r = await fetch(url);
  if (!r.ok) throw new Error("HTTP " + r.status);
  const dati = await r.json();
  tutti.push(...dati.items);
  console.log(`pagina ${dati.meta.page}/${dati.meta.pages}: ${dati.items.length} libri`);
  url = dati.links.next;                  // null sull'ultima pagina → esce dal while
}
console.log(tutti.length, "libri in totale; il più caro:", tutti[0].title, tutti[0].price);
```

<Aside type="caution" title="Rate limit">
A loop over every page makes many requests. The public server accepts 30 per minute per IP (120 if you run it locally): with `limit=100` you download 80 books in one call; with `limit=1` you need 80. Use the maximum `limit` when you want everything.
</Aside>

```python
import httpx
def tutti(url, params=None):
    out = []
    with httpx.Client() as c:
        while url:
            d = c.get(url, params=params).raise_for_status().json()
            out += d["items"]
            url, params = d["links"]["next"], None
    return out
consegnati = tutti("https://corso-api-json.giuseppebosi.com/api/v1/orders", {"status": "delivered", "limit": 100})
```

## Common mistakes

- **Passing `params` again on every page** together with `links.next`: the parameters get duplicated or overwritten (`page=2` repeated). Pass the parameters only the first time.
- **Counting `len(items)` instead of reading `meta.total`**: `items` is only the current page.
- **Ignoring `meta.pages` and doing `for page in range(1, 1000)`**: you ask for empty pages and burn the rate limit. Use `links.next`.
- **`sort=price desc`**: the syntax is `-price`. And the space, by the way, would need encoding.
- **Sorting on the client** after downloading only one page: you sort 20 elements out of 80.
