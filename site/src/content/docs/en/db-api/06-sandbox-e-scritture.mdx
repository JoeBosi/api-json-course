## Goals

- Create a **sandbox** (a private copy of the database) and use its token in every write request.
- Do `POST` (create), `PUT` (replace), `PATCH` (partially update), `DELETE` (delete) and read the responses: `201` + `Location`, `200`, `204`, `409`.
- Understand the difference between PUT and PATCH in practice.
- Reset or delete the sandbox.

## Theory

### Why a sandbox

A public server that anyone can write to would turn into chaos within an hour. This server uses a teaching compromise: the public dataset is **read-only**; whoever wants to write asks for a **token** with `POST /api/v1/sandbox`, and from then on every request carrying that token works on a **copy** of the database of their own. The token is a secret: whoever has it sees and changes your copy. It expires after 6 hours of inactivity (every request renews the timer).

The token is sent in the `Authorization: Bearer <token>` header (standard, [RFC 6750](https://www.rfc-editor.org/rfc/rfc6750)) or as `X-Sandbox-Token: <token>`. Without a token, a write answers `401` with the code `sandbox_required`.

### The four write verbs

| Verb | On the URL | Body | Typical response | Idempotent |
|---|---|---|---|---|
| `POST` | the **collection** (`/books`) | the new object | `201 Created` + a `Location` header with the new element's URL + the created object | no |
| `PUT` | the **element** (`/books/81`) | the **complete** object | `200` + the object | yes |
| `PATCH` | the element | **only the fields** to change | `200` + the object | in practice yes |
| `DELETE` | the element | none | `204 No Content` (empty body) | yes |

`PUT` vs `PATCH` is the distinction that most often surprises people: with `PUT` **the fields you do not send are cleared** (or set to their default), because you are replacing the whole representation. With `PATCH` they stay as they were.

### The server's rules (validation and integrity)

The server does not accept just anything: `title` not empty, `price ≥ 0`, `author_id` and `category_id` must **exist** (foreign keys), the ISBN must be unique. Violations come back as `422` (invalid data) and `409` (conflict with the current state: duplicate ISBN, a book present in orders). Chapters 7 and 13 for the details.

### 4. PUT: replacing everything

<Curl cmd={`curl -sS -X PUT https://corso-api-json.giuseppebosi.com/api/v1/books/81 \\
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \\
  -d '{"title": "Il mio primo libro (2a ed.)", "author_id": 3, "category_id": 2, "price": 14}' \\
  | jq '{id, title, price, pages, in_stock, tags, attributes}'`} spiega={[
  ['-X PUT', 'replaces the whole representation: the body must contain <strong>all</strong> the required fields (<code>title</code>, <code>author_id</code>, <code>category_id</code>, <code>price</code>)'],
  ['(no pages, tags, attributes)', 'and the omitted fields go back to their defaults: look at the response'],
]} />

```json
{ "id": 81, "title": "Il mio primo libro (2a ed.)", "price": 14.0, "pages": null, "in_stock": true, "tags": [], "attributes": {} }
```

`pages` has become `null`, `tags` empty, `attributes` empty, `in_stock` is back to `true`: it was a PUT. If you only wanted to change the title, you needed PATCH.

### 5. DELETE: two outcomes

<Curl cmd={`curl -sS -i -X DELETE https://corso-api-json.giuseppebosi.com/api/v1/books/1 -H "Authorization: Bearer $TOKEN"
curl -sS -i -X DELETE https://corso-api-json.giuseppebosi.com/api/v1/books/81 -H "Authorization: Bearer $TOKEN"`} spiega={[
  ['-X DELETE …/books/1', 'book 1 appears in existing orders (<code>order_items.book_id</code>): the foreign key protects it'],
  ['-X DELETE …/books/81', 'the book we created: no order mentions it'],
]} />

```
HTTP/1.1 409 Conflict
{"error":{"code":"book_in_orders","message":"Il libro compare in ordini esistenti: la chiave esterna impedisce di cancellarlo"}}

HTTP/1.1 204 No Content
```

`204` = done, and **there is no body** (careful not to call `.json()` on an empty response). A second `DELETE /books/81` would give `404`: the state is the same (idempotence), only the code changes.

## Python and TypeScript

The full cycle: create a sandbox → POST → PATCH → DELETE, checking the status and reading `Location`.

<Tabs syncKey="lang">
<TabItem label="Python">
```python
# python3 scritture.py
import httpx

base = "https://corso-api-json.giuseppebosi.com/api/v1"
with httpx.Client(base_url=base) as c:
    token = c.post("/sandbox").raise_for_status().json()["token"]
    c.headers["Authorization"] = f"Bearer {token}"      # da qui in poi tutte le richieste lo portano

    nuovo = {"title": "Il mio primo libro", "author_id": 3, "category_id": 2, "price": 12.5, "tags": ["novità"]}
    r = c.post("/books", json=nuovo)       # json= serializza e mette Content-Type: application/json
    r.raise_for_status()
    print(r.status_code, r.headers["location"])        # 201 …/api/v1/books/81
    libro = r.json()

    r = c.patch(f'/books/{libro["id"]}', json={"price": 9.9})
    print(r.status_code, r.json()["price"])            # 200 9.9

    r = c.delete(f'/books/{libro["id"]}')
    print(r.status_code, repr(r.text))                 # 204 ''  ← nessun corpo

    r = c.delete("/books/1")                           # FK: è in ordini
    print(r.status_code, r.json()["error"]["code"])    # 409 book_in_orders

    c.delete("/sandbox")                               # pulizia
```
</TabItem>
<TabItem label="TypeScript">
```ts
// node --experimental-strip-types scritture.ts
const base = "https://corso-api-json.giuseppebosi.com/api/v1";
const token = (await (await fetch(base + "/sandbox", { method: "POST" })).json()).token;
const headers = { Authorization: `Bearer ${token}`, "Content-Type": "application/json" };

const nuovo = { title: "Il mio primo libro", author_id: 3, category_id: 2, price: 12.5, tags: ["novità"] };
let r = await fetch(base + "/books", { method: "POST", headers, body: JSON.stringify(nuovo) });
if (!r.ok) throw new Error("HTTP " + r.status);
console.log(r.status, r.headers.get("location"));      // 201 …/api/v1/books/81
const libro = await r.json();

r = await fetch(`${base}/books/${libro.id}`, { method: "PATCH", headers, body: JSON.stringify({ price: 9.9 }) });
console.log(r.status, (await r.json()).price);          // 200 9.9

r = await fetch(`${base}/books/${libro.id}`, { method: "DELETE", headers });
console.log(r.status, JSON.stringify(await r.text()));  // 204 ""  ← nessun corpo: niente .json()

r = await fetch(`${base}/books/1`, { method: "DELETE", headers });
console.log(r.status, (await r.json()).error.code);     // 409 book_in_orders

await fetch(base + "/sandbox", { method: "DELETE", headers });   // pulizia
```
</TabItem>
</Tabs>

<Aside type="note">
In Python `json=` does three things: it serializes the dict, sets `Content-Type: application/json` and encodes in UTF-8. In JavaScript you do them by hand: `JSON.stringify` + the header. Forgetting the header is the most frequent mistake.
</Aside>

## Common mistakes

- **`.json()` on a 204**: empty body → `JSONDecodeError` / `SyntaxError: Unexpected end of JSON input`. Check the status first.
- **PUT with a partial body** thinking it is a PATCH: data cleared.
- **Token in single quotes** in curl (`'Bearer $TOKEN'`): 401.
- **Reusing an id after the reset**: `POST /sandbox/reset` brings the ids back to the initial dataset; book 81 no longer exists.
- **Sharing the token** (in a screenshot, in a repo): anyone can write into your copy.

## Summary

`POST /sandbox` → token → `Authorization: Bearer`. POST creates (201 + Location), PUT replaces, PATCH touches up, DELETE deletes (204). Foreign keys protect the data (409). Next chapter: every error an API can respond with, and how to handle them in code.
