## Obiettivi

- Capire cosa fa un'API quando restituisce "statistiche": `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` calcolati dal database.
- Leggere una risposta aggregata e sapere da quali tabelle e JOIN viene.
- Usare `GET /stats` e `GET /stats/sales?group_by=…&from=…&to=…` con curl, Python e TypeScript.
- Disegnare un grafico testuale partendo dai numeri aggregati.

## Teoria

Finora hai chiesto **righe**: un libro, una lista di ordini. Le aggregazioni chiedono invece **numeri riassuntivi** su molte righe: quanti libri per categoria, l'incasso per mese, il voto medio di un autore. In SQL si ottengono con le **funzioni di aggregazione** e con `GROUP BY`:

| Funzione | Cosa calcola | Esempio nel dataset |
|---|---|---|
| `COUNT(*)` | numero di righe del gruppo | libri per categoria |
| `COUNT(DISTINCT x)` | valori distinti | ordini distinti che contengono un libro |
| `SUM(x)` | somma | incasso (`quantity * unit_price`) |
| `AVG(x)` | media | prezzo medio |
| `MIN(x)` / `MAX(x)` | estremi | libro più economico / più caro |

`GROUP BY colonna` divide le righe in gruppi (uno per valore della colonna) e ogni funzione lavora **dentro** il gruppo. `HAVING` filtra i gruppi *dopo* l'aggregazione (mentre `WHERE` filtra le righe *prima*).

Un'API "fatta bene" non ti fa scaricare 300 righe di `order_items` per sommarle sul client: espone un endpoint che fa il calcolo nel database e restituisce solo il risultato. È più veloce, e soprattutto il risultato è **coerente** (una sola fonte di verità).

<Aside type="note" title="Da quali tabelle vengono i numeri?">
`/stats/sales` unisce **quattro** tabelle: `orders` (data e stato) → `order_items` (quantità e prezzo) → `books` (categoria, autore) → `categories`/`authors`/`customers` a seconda di `group_by`. La query esatta la vedrai nel capitolo 12 quando la scriverai tu con `/sql`.
</Aside>

## Python e TypeScript

Vendite per città, trasformate in un grafico a barre testuale. Il lavoro pesante (somme e raggruppamenti) lo fa il server; il client si occupa solo di ordinare e disegnare.

<Tabs syncKey="lang">
<TabItem label="Python">
```python
# pip install httpx   →   python3 vendite.py
import httpx

BASE = "https://corso-api-json.giuseppebosi.com/api/v1"
r = httpx.get(f"{BASE}/stats/sales", params={"group_by": "city"}, timeout=10)
r.raise_for_status()                       # solleva un'eccezione se lo status non è 2xx
righe = r.json()["items"]
massimo = max(x["revenue"] for x in righe)
for x in sorted(righe, key=lambda x: -x["revenue"]):
    barra = "█" * round(30 * x["revenue"] / massimo)
    print(f"{x['city']:<8} {barra:<30} {x['revenue']:>8.2f} € ({x['orders']} ordini)")
```
</TabItem>
<TabItem label="TypeScript">
```ts
// node --experimental-strip-types vendite.ts
const BASE = "https://corso-api-json.giuseppebosi.com/api/v1";
type Riga = { city: string; orders: number; books_sold: number; revenue: number };

const r = await fetch(`${BASE}/stats/sales?group_by=city`);
if (!r.ok) throw new Error(`HTTP ${r.status}`);
const { items } = (await r.json()) as { items: Riga[] };
const massimo = Math.max(...items.map((x) => x.revenue));
for (const x of [...items].sort((a, b) => b.revenue - a.revenue)) {
  const barra = "█".repeat(Math.round((30 * x.revenue) / massimo));
  console.log(`${x.city.padEnd(8)} ${barra.padEnd(30)} ${x.revenue.toFixed(2).padStart(8)} € (${x.orders} ordini)`);
}
```
</TabItem>

## Esercizio

1. Quale categoria ha l'**incasso** più alto? È la stessa con più **libri venduti**? (usa `group_by=category`).
2. Scrivi uno script che chiama `/stats/sales?group_by=month` e stampa il mese migliore e quello peggiore.
3. Perché `orders` in `/stats/sales` usa `COUNT(DISTINCT o.id)` e non `COUNT(*)`?

<details>
<summary>Soluzione</summary>

1. Con `group_by=category`: **saggistica** ha l'incasso più alto (1489,55 €) **ed è anche prima per copie vendute** (82), seguita da narrativa (1460,82 € e 64 copie). Qui le due classifiche coincidono, ma non è detto: più in basso cucina vende 39 copie con un incasso (742,25 €) inferiore a quello di fantascienza, che ne vende 28 (834,10 €). Dipende dal prezzo medio.
2. Dopo aver ottenuto `items`, `max(items, key=lambda x: x["revenue"])` e `min(...)` in Python; in TS ordina con `sort` e prendi il primo e l'ultimo.
3. Perché la query unisce `orders` a `order_items`: un ordine con tre righe compare tre volte nel JOIN. `COUNT(*)` conterebbe le righe, `COUNT(DISTINCT o.id)` gli ordini.
</details>

## Errori comuni

- **Aggregare sul client** scaricando tutte le righe: lento, e con la paginazione rischi di sommare solo la prima pagina.
- **Confondere `WHERE` e `HAVING`**: `from`/`to` filtrano le *righe* (WHERE), "solo le categorie con più di 5 libri" filtra i *gruppi* (HAVING).
- **Dimenticare gli stati**: un incasso che include gli ordini annullati è sbagliato. Chiedi sempre all'API (o alla documentazione) cosa esclude.
- **Medie di medie**: la media dei prezzi medi per categoria non è il prezzo medio del catalogo.

## In sintesi

Le aggregazioni sono numeri calcolati dal database su gruppi di righe; l'API le espone come endpoint dedicati (`/stats`, `/stats/sales`) con parametri per scegliere il raggruppamento e il periodo. Nel prossimo capitolo passerai dall'altra parte: costruirai tu la query, in JSON, con `POST /query`.
