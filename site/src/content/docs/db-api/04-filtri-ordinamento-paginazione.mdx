## Obiettivi

- Combinare più filtri nella query string e sapere quali valori accetta ciascuno.
- Ordinare con `sort=campo` / `sort=-campo`.
- Capire la paginazione a **offset** (`page`/`limit`) e i suoi limiti; leggere `meta` e `links`.
- Scrivere un ciclo che scarica **tutte** le pagine seguendo `links.next`, in Python e TypeScript.
- Riconoscere gli errori di parametri (400, 422) prima che diventino bug.

## Teoria

### Filtrare

Una collezione può avere migliaia di elementi: il client dice *quali* vuole con parametri di query. Su `/api/v1/books` sono disponibili:

| Parametro | Cosa fa | Esempio |
|---|---|---|
| `q` | testo contenuto nel titolo (`LIKE %q%`, senza distinzione maiuscole) | `q=trieste` |
| `author_id` | libri di un autore (chiave esterna) | `author_id=4` |
| `category` | **slug** della categoria, **incluse le sottocategorie** | `category=narrativa` prende anche gialli, fantascienza, storici |
| `tag` | libri con quel tag (relazione N-N) | `tag=premio` |
| `min_price`, `max_price` | intervallo di prezzo (inclusivo) | `min_price=10&max_price=20` |
| `year_from`, `year_to` | intervallo di anno di pubblicazione | `year_from=2000` |
| `language` | codice lingua | `language=en` |
| `in_stock` | `true`/`false` | `in_stock=true` |
| `format` | valore di `attributes.format`, una **colonna JSON** | `format=tascabile` |

I filtri si sommano con **AND**: `category=gialli&max_price=15` = gialli **e** sotto i 15 €. (Per OR e condizioni complesse c'è `POST /query`, capitolo 11.)

I valori arrivano al server come **stringhe**: è il server a convertirle (`min_price=10` → numero) e a validarle. Se mandi `min_price=dieci` ottieni 422.

### Ordinare

`sort=price` crescente, `sort=-price` decrescente: il segno meno davanti al nome è una convenzione diffusa (JSON:API, molte API REST). Campi ammessi qui: `id`, `title`, `price`, `year`, `pages`, `created_at`, `rating`. A parità di valore il server ordina per `id`, così l'ordine è **stabile** tra una pagina e l'altra (senza questa regola, un elemento potrebbe comparire in due pagine o in nessuna).

### Paginare

Con 80 libri ok, con 80.000 no: le risposte sono divise in **pagine**.

- `limit` = elementi per pagina (qui default 20, **massimo 100**).
- `page` = quale pagina, da 1.
- Il server calcola `OFFSET (page-1)*limit` nella query SQL: è la paginazione **a offset**. Semplice, ma con offset enormi diventa lenta e, se nel frattempo qualcuno inserisce un elemento, le pagine "scivolano". L'alternativa — la paginazione a **cursore** (`?after=<id>`) — è accennata nel capitolo 14.

La risposta ti dice dove sei e come continuare:

```json
"meta":  { "page": 1, "limit": 3, "total": 4, "pages": 2 },
"links": { "self": "…page=1…", "next": "…page=2…", "prev": null }
```

`links.next` è **null** sull'ultima pagina: è la condizione di uscita del ciclo. E contiene già tutti i filtri: il client non deve ricostruire nulla.

## Python e TypeScript: scaricare tutte le pagine

Il pattern è sempre lo stesso: parti dall'URL con i filtri, poi **segui `links.next` finché non è null**. Attenzione a un dettaglio: i parametri vanno passati solo alla **prima** richiesta, perché `next` li contiene già.

<Tabs syncKey="lang">
<TabItem label="Python">
```python
# python3 tutte_le_pagine.py
import httpx

url = "https://corso-api-json.giuseppebosi.com/api/v1/books"
params = {"category": "saggistica", "sort": "-price", "limit": 10}
tutti = []
with httpx.Client() as client:            # un Client riusa la connessione tra le richieste
    while url:
        r = client.get(url, params=params)
        r.raise_for_status()
        dati = r.json()
        tutti.extend(dati["items"])
        print(f'pagina {dati["meta"]["page"]}/{dati["meta"]["pages"]}: {len(dati["items"])} libri')
        url, params = dati["links"]["next"], None   # next contiene già filtri e limit
print(len(tutti), "libri in totale; il più caro:", tutti[0]["title"], tutti[0]["price"])
```
</TabItem>

<Aside type="caution" title="Rate limit">
Un ciclo su tutte le pagine fa molte richieste. Il server pubblico ne accetta 30 al minuto per IP (120 se lo fai girare in locale): con `limit=100` scarichi 80 libri in una chiamata; con `limit=1` ne servono 80. Usa il `limit` massimo quando vuoi tutto.
</Aside>

import httpx
def tutti(url, params=None):
    out = []
    with httpx.Client() as c:
        while url:
            d = c.get(url, params=params).raise_for_status().json()
            out += d["items"]
            url, params = d["links"]["next"], None
    return out
consegnati = tutti("https://corso-api-json.giuseppebosi.com/api/v1/orders", {"status": "delivered", "limit": 100})

## Errori comuni

- **Ripassare `params` a ogni pagina** insieme a `links.next`: i parametri vengono duplicati o sovrascritti (`page=2` ripetuto). Passa i parametri solo la prima volta.
- **Contare `len(items)` invece di leggere `meta.total`**: `items` è solo la pagina corrente.
- **Ignorare `meta.pages` e fare un `for page in range(1, 1000)`**: chiedi pagine vuote e bruci il rate limit. Usa `links.next`.
- **`sort=price desc`**: la sintassi è `-price`. Lo spazio, tra l'altro, va codificato.
- **Ordinare lato client** dopo aver scaricato solo una pagina: ordini 20 elementi su 80.

## In sintesi

Filtri in AND nella query string (anche su relazioni e colonne JSON), `sort=-campo`, `page`/`limit` con massimo 100, e `links.next` per scorrere tutto. Nel prossimo capitolo seguiamo le **chiavi esterne**: da un ordine ai suoi libri, ai loro autori, in una richiesta sola.
